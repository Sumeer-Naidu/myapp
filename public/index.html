Security measures implemented

Applied

Secrets kept out of code

The database password is stored in a Kubernetes Secret (patient-db-secret) and injected into the pod at runtime.

Applied

Non-root container

The Docker image runs as user 1000 and the pod sets runAsUser: 1000, so a compromised app has limited power.

Applied

No privilege escalation

The pod sets allowPrivilegeEscalation: false, so processes cannot gain extra rights.

Applied

Image vulnerability scan

Trivy scans every Docker image for HIGH and CRITICAL vulnerabilities before it is pushed and deployed.

Applied

Secret scan of source code

Trivy checks the repository for leaked passwords and keys, and fails the build if it finds any.

Applied

Protected pipeline credentials

Docker Hub login lives in the Jenkins credential store and is masked in build logs.

DevSecOps pipeline

  1. CheckoutPull code from Git
  2. Secret scanFind leaked keys
  3. BuildDocker image
  4. Image scanTrivy CVE check
  5. PushDocker Hub
  6. DeployKubernetes, hardened pod

Highlighted stages are the security gates. If a gate fails, the pipeline stops and nothing reaches production.

Why this matters for healthcare

Confidentiality

Only authorized staff should see patient records. Secrets and access are locked down.

Integrity

Records must not be changed without a trace. Signed, scanned images prevent tampered software.

Compliance

Supports HIPAA, GDPR and India's DPDP Act by finding weaknesses before patient data is exposed.
